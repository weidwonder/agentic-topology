# agentic-topology

> 本文按 RFC 2119 解释 MUST / MUST NOT / SHOULD / MAY。
> **本技能是自足的**：不引用、不依赖任何其他技能。

## 它解决什么

多 agent 系统超过三四个 agent 之后，编排关系只存在于代码和各自的提示词里，没有全貌。接手、排查、讲解都要重新通读一遍。

这个技能把那份全貌读出来、画出来、并且能点开下钻。

**它只陈述事实，不下判断**——不评价架构好坏、不给改进建议。用途是让人**看清楚到能自己下判断**。

## 两条路径

| 路径 | 什么时候用 | 怎么走 |
|---|---|---|
| **自动分析**（主路径） | 使用者指着一个仓库或组件说"画一下它的编排" | §流程 四步，走完为止 |
| **手写描述**（兜底） | 已经有一份写好的描述；或分析整体失败 | 直接跳到 §出图 |

## 加载点清单

**MUST 在触发时才取、只取那份；MUST NOT 提前预读，MUST NOT 凭记忆代替取用。**

| 触发条件 | 加载 | 为什么此刻需要 |
|---|---|---|
| 每次唤起 | 本文全文 | 分路径与四步流程都在这里 |
| 要动手填任何字段 | `references/编排描述格式.md` | 字段契约、闭集取值、YAML 子集边界、校验规则，填之前就要在手 |
| 要判"这算一个节点还是两个" | `references/节点粒度约定.md` | 判据只在那里；不看它切出来的节点数不可复核 |
| 要开始读源码抽取 | `references/抽取纪律.md` | 真相方向、允许与禁止、读不出来怎么办、自查清单 |
| 要写任何会显示在图上的文字 | `references/界面用语表.md` + `references/抽取纪律.md` §3bis | 前者管框架文案的用词对照与标识符不翻译的例外，后者管描述正文怎么写 |
| 想看一份能直接改的样例 | `assets/templates/example.topology.yaml` | 最小完整样例 |
| 要出**英文界面**的图（`--lang en`） | `assets/templates/example-en.topology.yaml` | 同一份结构的英文样例。图上的正文一律不翻译（见 §出图），所以英文图要的是一份正文本来就是英文的描述 |

## 不加载点清单

上面那张表是正向的——到了那个时刻才取那一份。这张是反向的：

**在写出第一版 `.topology.yaml` 之前，MUST NOT 去读渲染器源码、校验器源码、布局算法、
测试与 `assets/` 下的页面骨架（即 `scripts/`、`tests/`、`assets/page-shell/` 这几处的实现代码）。**
抽取阶段的上下文额度要留给被分析项目的源码——这个技能自己是怎么把描述变成图的，
对写描述这件事没有帮助，读它是在烧掉本该花在被分析项目上的注意力。

只有同时满足两条才允许破例去读：报错文本本身解释不了这是个什么内部行为，
**且**已经按诊断信息（`evidence`、`supportedFixes`，见 §出图）改过两轮仍然不通过。

## 流程

### 第 1 步：概览目标项目的文档架构

看清楚有哪些文档、放在哪、大致讲什么。**只建立导航感，不采信。**

### 第 2 步：向使用者问一次

> "除了源码，有没有可直接参考的、准确表示项目情况的需求与代码架构文档？"

- 指认的文档登记为**导航与理解辅助**，用来快速定位该读哪些源码文件，**不作为任何一条事实的来源**。
- **不作答时降级为自行概览，MUST NOT 阻塞。**
- **只问这一次**，MUST NOT 在抽取过程中反复回来问。

### 第 3 步：读源码抽取实体，填出描述

**两份契约 MUST 错开加载，MUST NOT 一次性都读进来**——它们合起来比这份 SKILL.md 大一个数量级，
而这一步紧接着还要读被分析项目的源码：

1. **动手读源码之前**：加载 `references/抽取纪律.md`（真相方向、允许与禁止、读不出来怎么办）。
2. **读完一批、真要动手填字段时**：再加载 `references/编排描述格式.md`（字段契约与闭集取值）。

**图上的字怎么写，和抽得准不准同样重要**：除代码位置之外的所有正文（方块名、职责、收什么、
交出什么、起什么作用、终点条件、信息说明）**MUST 按 `抽取纪律.md` §3bis 写**——读者是一个
没看过这个项目代码的人，他要能只看这张图就说出这套东西怎么转。抽得再全，写成一串只有
读过源码才懂的黑话，这张图对他就是白出的。

**目标超过 1 万行源码或 20 个文件时，MUST 分批读、每批读完当场落盘**
（`抽取纪律.md` §6bis）。一次性读完再动笔会在读到后面时挤掉前面，
而且**症状是静默的**——产出的描述看不出哪些结论是在记忆已经模糊之后写的。

写出 `<主题>.topology.yaml`。**建文件时 `analysis_complete` MUST 先写 `false`，全部读完并自查过才改
`true`**——分批落盘时中途写成 `true`，产出的图会声称分析完整，而那正是下面禁止行为的第 2 条要挡的事。
（这个字段的完整语义见 `编排描述格式.md` §2 顶层结构。）

**落点 MUST 在被分析项目之外**——写进去就违反了下面禁止行为的第 1 条（「不新建、不改写」），
而且接下来出图也会被拒。使用者指定了位置就用那个（仍 MUST 核对它不在目标项目里）；
没指定时按这个顺序选：

1. 你**当前工作目录**，前提是它不在被分析项目内；
2. 否则用被分析项目的**父目录**；
3. 两者都不合适就**问使用者要一个位置**——MUST NOT 为了往下走而写进目标项目。

**先判断再动笔**：被分析项目的路径就是描述里的 `source_project`，
拿它和你打算写入的路径比一比即可。

### 第 4 步：出图，并把结果交给使用者

**MUST 做完这一步才算完**。只交一份 `.topology.yaml` 就收工，使用者还得自己去敲渲染命令——
而这个技能的整个意义就是让他们**一句话之外什么都不用做**。

跑下面的 `render.mjs`，然后把三样东西告诉使用者：**产出的 HTML 绝对路径**、
**几个方块几条连线**、**核对清单有几处要他们自己去核实**（这三样 `render.mjs` 成功时会直接打印）。

## 走一遍长什么样

（下面的路径与数字都是虚构的，只用来说明四步怎么衔接。）

使用者在 `~/work/demo-support-bot` 里说了一句「画一下这个项目的编排」。

- **第 1 步**：扫一遍目录，看到 `docs/` 下有 3 份文档、`src/agents/` 下有 4 个文件。只记路，不采信。
- **第 2 步**：问一次「有没有可直接参考的需求与代码架构文档？」使用者没回。不追问，降级为自行概览。
- **第 3 步**：先加载 `抽取纪律.md`，开始读源码。目标约 6000 行，没过分批线，一次读完。
  读到两个装配了系统提示词的会话（分诊、答复）、三段确定性代码、一个岔路口。
  真要落字段时再加载 `编排描述格式.md`。在当前工作目录（不在 `demo-support-bot` 里）建
  `demo-support-bot.topology.yaml`，**`analysis_complete` 先写 `false`**；其中「工单分类结果」这份
  信息在两处出现、读不出是不是同一份，按纪律**拆成两份都标 `inferred`**，不并掉。全部填完自查后改 `true`。
- **第 4 步**：
  ```bash
  node <本技能根目录>/scripts/render.mjs demo-support-bot.topology.yaml -o demo-support-bot.topology.html
  ```
  stdout 打印 `输出：/Users/x/work/demo-support-bot.topology.html` 和 `6 个方块 · 8 条连线 · 2 处要你核实`。
  把这三样告诉使用者，**路径取打印的那个**。

校验没过的那种走法：`render.mjs` 不产出任何 HTML，逐条打印问题。照着每条的 `evidence` 与
`supportedFixes` 改，改完重跑——只要错误条数创新低就继续，连续两轮没创新低就停下、把剩余清单交给使用者。

## 出图

```bash
# 只校验，不出图
node <本技能根目录>/scripts/validate.mjs <描述文件>

# 机器可读的校验结果（信封里有 schemaVersion，errors/warnings 每条都带 evidence 与 supportedFixes）
node <本技能根目录>/scripts/validate.mjs <描述文件> --format json

# 出图（内部先校验，通过才产出）
node <本技能根目录>/scripts/render.mjs <描述文件> -o <主题>.topology.html

# 出图并要一份机器可读收据（描述与产出各自的 sha256、字节数，以及节点/连线/核对清单三个数）
node <本技能根目录>/scripts/render.mjs <描述文件> -o <主题>.topology.html --json

# 出英文界面的图（默认 zh）
node <本技能根目录>/scripts/render.mjs <描述文件> -o <主题>.topology.html --lang en

# 覆盖已有的同名产物（默认不覆盖，见下）
node <本技能根目录>/scripts/render.mjs <描述文件> -o <主题>.topology.html --force
```

`--lang` 取 `zh`（默认）或 `en`，**只切界面文案；描述里的正文一律不翻译**——方块名、职责、每份信息
是什么，都按描述里写的原样上图。所以要一张正文是英文的图，得让描述的正文本来就是英文
（样例见加载点清单里的 `example-en.topology.yaml`）。取值不认识会直接报错并列出认得哪几个，
**不会静默回落成中文**——那会让人以为 `--lang en` 生效了，实际拿到一张中文图。

**目标文件已存在时默认不覆盖**，而是自动另存为 `<主题>.2.topology.html` 并打印「已有一份，已另存为 …」。
所以**报给使用者的路径 MUST 取 stdout 打印的那个，MUST NOT 凭 `-o` 的值去猜**。确定要盖掉原件时才加 `--force`。

`--format json` 的每条 `errors`/`warnings` 都带三样东西：`evidence`（这一条诊断实测到的值，
比如不合法的枚举值和允许取值域）、`supportedFixes`（允许用来修它的手段，来自一张固定的码
→ 修复手段对照表）、`line`（行号）。改的时候照着 `evidence` 和 `supportedFixes` 定位就够，
不必去读校验器源码反推它想要什么——那正是下面「不加载点清单」要挡住的事。

`--json` 只在真出了图时才有输出；校验不过或写不出去时仍走原来的报错通路与退出码，不会
输出一份假装成功的收据。

`<本技能根目录>` = 你加载的这份 `SKILL.md` 所在的目录。

**要求 Node ≥ 18**，零依赖、不联网。命令跑不起来且报的是语法错或模块解析错时，
先 `node -v` 看版本——低于 18 时的报错不会告诉你真因。

**`-o` 的文件名 MUST 以 `.topology.html` 结尾**，否则会被拒绝（`输出路径必须以 .topology.html 结尾`）。
**输出路径 MUST 落在被分析项目之外**，否则同样被拒（`不能把图写进被分析的项目里`）——
那会违反下面禁止行为的第 1 条。

退出码：`0` 通过 · `2` 校验不通过 · `3` 语法错或文件读不了 · `1` 程序自身异常。

**校验不通过时不会产出任何 HTML**，而是逐条打印哪个方块、哪条线、缺哪一项。照着改下一轮。
**停不停 MUST 看错误条数，不是看轮数**：只要这一轮的错误条数比此前任何一轮都更少，就 MUST 继续改；
连续两轮都没能刷出比此前更低的错误数，MUST 停下，把剩余的问题清单原样交给使用者。
**MUST NOT 编造字段值把它凑过去。**

产物是**一个可离线打开的单文件网页**——断网能看、能直接发给别人、不依赖任何服务。

## 禁止行为（每条都是 MUST NOT）

1. **MUST NOT 修改目标项目任何文件。** 全程只读。
2. **MUST NOT 把「只是猜的」或「没查出来」呈现为「查实了」。**
3. **MUST NOT 编造**项目里不存在的方块、工具、MCP、Skill、子代理或连线。
4. **MUST NOT 给出架构好坏的判断**——不写"设计得不好""缺少重试是个隐患""建议加上限"这类话。
5. **MUST NOT 把项目文档当作某条事实的唯一来源。** 源码是唯一真相源，文档只作弱参考。
6. **MUST NOT 把目标项目内容发送至任何外部服务。**
7. **MUST NOT 为了让校验通过而编造字段值。**
8. **MUST NOT 静默裁掉方块或连线**让图好看——过密靠分堆折叠和筛选解决。

## 读不出来的时候

**明说没读懂哪部分**，把对应的方块或字段标成「没查出来」，让它进核对清单。

**MUST NOT 产出空图，MUST NOT 猜测结构去把图填满。** 整体读不出来时明说卡在哪，提示使用者改用手写描述那条路。

## 一句话

读源码填出一份描述，让确定性的校验器决定它能不能变成图；查实了的画实线，只是猜的和没查出来的画虚线并单独列一份清单——**这张图只说它查到了什么，不说它觉得怎么样。**
