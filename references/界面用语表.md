# 界面用语表

> 本文按 RFC 2119 解释 MUST / MUST NOT / SHOULD / MAY。
> **本文是自足的**：不引用任何其他技能或外部文档。

## 为什么有这张表

同一个东西有三个名字，各管一段：

- **契约用语**：写文档、讨论设计时用的词。
- **描述文件里的 key**：机器读的字段名，ASCII、稳定、进错误消息与测试断言。
- **界面上的说法**：使用者在图上看到的字。**MUST 是大白话，刚入行的人不需要任何背景知识就能看懂。**

三者一一对应，**MUST NOT 在这三套之外再造第四个说法**。

## 三条硬规矩

1. **载体取值 `bundle` 在界面上 MUST 写「一份打包好的数据」**，MUST NOT 写成「结构体」这类技术词。
2. **专有名词保留原词，但 MUST 在旁边给一句白话解释**：`MCP` 写成「外挂的能力（MCP）」，`Skill` 写成「装的技能（Skill）」。
3. **标识符 MUST NOT 翻译**——这是唯一的例外，且是硬性的：

   `tools` / `mcp` / `skills` 数组里的每个字符串（如 `read`、`grep`、`agent_fs`、`todo_write`、`write`）、`system_prompt.file` 的文件名、`source.refs` 里的路径与函数名，一律**原样照抄**。

   **为什么**：这些是使用者要拿去在代码里搜的字符串。译成中文之后就搜不到了，也对不上项目里的实际配置。

## 判据

界面上出现的每个词，MUST 能被一个刚接触 agent 开发的人直接读懂。**需要先解释一遍才能理解的浓缩术语 MUST NOT 出现在界面里。**

自查方法：把渲染出来的 HTML 剥掉 `<style>` 与 `<script type="application/json">` 之后，正文里 MUST NOT 出现「节点」「边」「传递物」「并发数」「可信度」「载体」「结构体」这几个词。
